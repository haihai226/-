# 开工指南

## 一、开工前你自己做的 5 件事（AI 做不了）

1. 把方案文档导出成 Markdown，存为 `docs/plan.md` 并提交。
2. `CLAUDE.md` 放仓库根目录，`docs/TASKS.md`、`docs/KICKOFF.md` 放 `docs/`，提交。
3. 注册并拿到三类密钥：STT（FunASR 自部署则不需要）、TTS（MiniMax 或 Fish）、LLM（Qwen3 或 DeepSeek）。
   写进 `.env`（照 `.env.example` 的变量名），**不要**贴进聊天，不要提交。
4. 教材 PDF 放到 `data/kb/`，先放一本就够。
5. 本机装好 Docker、uv、Node 20+；把测试和 docker 命令加进 Claude 的允许列表，免得每一步都要你点确认。

## 二、第一条提示词（原样发给它）

```
先读 CLAUDE.md、docs/plan.md、docs/TASKS.md，读完告诉我你理解的目标和硬规则，用五句话。
然后从阶段 0 开始，按 TASKS.md 顺序执行。阶段 0 的三个任务可以合并成一个计划，
先给我看计划，我批准后再动手。
每完成一个任务：跑测试、提交到任务分支、在 docs/PROGRESS.md 追加一行。
只在 CLAUDE.md "需要我的事"清单上的事项停下来问我，其它决定自己做并把理由写进 PROGRESS.md。
不要修改 Pipecat 和 DeepTutor 的源码。
现在开始。
```

## 三、之后每个任务的提示词

一个任务开一个新会话（上下文别拖长），发：

```
读 CLAUDE.md 和 docs/PROGRESS.md 最后三行，然后做 docs/TASKS.md 里的 T<编号>。
先给计划，批准后再动手。做完给我：测试输出、延迟数字（如果涉及）、未验证的部分。
```

阶段门槛时发：

```
现在检查 Gate <编号>。把每一条门槛的实测数字列出来，过了就写进 PROGRESS.md，
没过就告诉我差在哪、你打算怎么改，不要直接进下一阶段。
```

## 四、你怎么验收（每次只花 5 分钟）

- 只看 `docs/PROGRESS.md` 的证据列和未验证列，不看聊天记录。
- 它说"测试通过"，你抽查一次：自己跑 `uv run pytest`。
- 它说"延迟达标"，你看 `logs/latency.jsonl` 算出来的 P95，不看它的总结。
- 它改了 `adapter/contracts.py` 或加了依赖而没问你 → 退回重做。
- 发现它在改 `vendor/DeepTutor` 或 `.venv` 里的东西 → 退回重做。

## 五、四个必须你出面的节点

| Gate 1 | 戴耳机试听：音色、延迟、打断手感 | 第 2 周末 |

| Gate 3 | 亲自试插话和换问题 | 第 4 周末 |

## 六、它大概率会犯的四个错，提前知道

1. 凭记忆写旧版 Pipecat 的 API —— 阶段 0 的源码摘录就是为此，发现它没引用 api-notes 就让它回去读。
2. 用同步调用或 sleep "修"延迟 —— CLAUDE.md 已禁止，看到就退回。
3. 跑不起来就编"测试通过" —— 所以第一件事是你自己把环境跑通一次。
4. 一个会话做太多任务后忘了规则 —— 所以一个任务一个新会话。
